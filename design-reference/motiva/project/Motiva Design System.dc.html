MOTIVA DESIGN SYSTEM · v1.0

The foundation, not the wallpaper.

This turns the Visual Manifesto's philosophy into tokens, materials and components — the shared vocabulary every future Motiva screen is built from. Where the manifesto was right, we specify it precisely. Where it was vague, we make a call here.

ONE REFINEMENT TO THE MANIFESTO

The manifesto named two brand hues plus an "attention" concept but left it loose. Locking it now: three semantic hues total, no more — violet (action), teal (progress/done), rose (attention/blocking). Everything else, forever, is neutral ink on paper. This is the single rule most responsible for keeping Motiva from drifting back into admin-dashboard territory as the product grows.

v2.0 · AMBIENT IS THE IDENTITY, NOT VIOLET

Earlier versions of this system treated violet as the brand and Ambient as a decorative wash on top of it. That reads as "a purple product," not as Motiva. Flipping it: the violet → neutral → aqua Ambient composition is the primary visual signature — the thing that makes a Dashboard, a Requests list and a Mentor workspace obviously the same product at a glance. Violet steps down to an accent: primary actions, active states, Motiva Pulse, and the occasional small brand mark. It no longer colors navigation, links, avatars, tags, KPI tiles or decorative surfaces just because it's the brand hue.

Teal now carries progress, journey and on-track status end to end (milestone fills, "current stage" labels, links). Rose stays reserved for genuine attention, risk or blocking states — never a generic warning. See MOTIVA ACROSS THE PRODUCT below for the real screens, side by side.

Rules for using color: Ambient — not violet — is Motiva's primary visual signature; it lives at the page and section level and is what makes every screen recognizably the same product. Violet is an accent, used selectively for primary actions, active states and Motiva Pulse — never for navigation, links, statuses, badges and decoration all at once. Teal carries the journey: progress, completed, on-track. Rose is reserved for genuine attention, risk or blocking — never a generic warning. If a screen needs a fourth color to communicate status, it's not a color problem, it's a wording problem: say it in words.

Hierarchy: ink carries all reading. Muted ink is metadata. Semantic color is never used for decoration — only for meaning the student must register or act on. Ambient is atmosphere, not a status color.

Spacing & Radius

4px base unit → 4·8·12·16·24·32·48·64·96. Rows use 12–16px internal padding; modules use 24–32px; page sections separate by 64–96px. Vertical rhythm > horizontal density — when in doubt, add vertical space, not another border.

02 · MATERIALS

Five surfaces, each with a job

Ambient — the primary brand surface

One RTL composition, three intensities: Hero (100%, page-opening), Focus (~65%, one module), Context (~30–40%, smaller moments). Violet originates left, dissolves through a quiet neutral center, to a faint aqua/teal on the right — same recipe everywhere. Lives at the page/section level; never turns cards, buttons or badges into gradient surfaces.

Paper

The default background of every workspace page. Matte, opaque, warm off-white. No blur.

Elevated paper

White + shadow-md. For the one or two modules per page that deserve isolation (milestone tracker, a highlighted action).

Floating surface

Modals, drawers, menus. Highest elevation in the system — used sparingly, always dismissible.

Glass

Rationed to one instance per screen, max: the sidebar/nav strip when it sits over an ambient threshold. Never for content surfaces — glass over text hurts legibility.

04 · MOTION

Confident, slow, never bouncy

Timing: 120ms micro (hover), 200ms interaction (open/close a row), 320ms module transitions, 480–600ms ambient fades.
Easing: ease-out for anything entering, ease-in-out for ambient. No spring, no overshoot, no bounce — ever.
Hover: a 2–4% lift in ink weight or a 1px shadow increase. Never a color swap or scale-up.
Focus: 2px violet ring, offset 2px. Keyboard-visible always, not just on click.
Loading: a quiet pulse on the paper surface, not a spinner. The product waits calmly, it doesn't spin anxiously.
Success: a contained 400ms ambient bloom + signature glow on the element, then settle. Rare, so it stays meaningful.
Ambient breathe (v1.1): 3.2s ease-in-out infinite box-shadow pulse (4px→9px spread, 14%→5% opacity, brand hue only). Marks exactly one "you are here" element per screen — a current timeline node, an in-progress marker. Never on hover, never on more than one element at once.

05 · ICONOGRAPHY

One outline family, one job each

1.5px stroke, rounded caps and joins, drawn on a 24px grid, single weight throughout. The signature glow dot is the only filled mark in the system — that contrast is what makes it read as special. Icons appear next to nav destinations and primary actions; they disappear inside dense metadata rows (a due date doesn't need a calendar glyph next to it — the word is enough). When in doubt, cut the icon before adding a second color to it.

06 · LAYOUT SYSTEM

Same skeleton, different rhythm

Sidebar: fixed 248px, paper material, glass only when a threshold ambient is behind it. Workspace content caps at ~1040px so reading lines stay short. Header is a single slim row — greeting/title + 1–2 icon actions, never a second toolbar stacked under it.

Dashboard

Widest rhythm: one milestone card + rows beneath. Ambient greeting at top. Feels like opening a daily planner.

My Tasks

Densest rhythm: grouped rows by status, tightest spacing scale, no ambient beyond the header. Feels like a productivity tool.

Requests

Conversational rhythm: taller rows with more breathing room, since each is a small exchange, not a checklist item.

07 · PRODUCT RULES

The rulebook

  1. Ambient marks moments, never locations.
  2. One workspace per page — not a grid of competing panels.
  3. Rows are the default; cards are earned.
  4. Three semantic hues, total, forever: violet, teal, rose.
  5. Status is a word + the signature glow — never a colored badge rainbow.
  6. One icon family, outlined, one weight. No emoji, anywhere.
  7. No motion bounces, springs, or celebratory bursts.
  8. One glass surface per screen, maximum — never on a content/text surface.
  9. Every screen leads with "what needs you," not "what's your status."
  10. Dashboard, Tasks, Requests share materials but tune rhythm to their job.
  11. When unsure, remove a color or a container before adding one.
  12. One decision per screen — merge modules that would tell the student the same "do this next" (v1.1).
  13. Hero is a Project Command Center, not a greeting — project name, overall progress, milestone timeline, quiet numeric summary (v1.2, supersedes v1.1).
  14. Order sections by decision priority: act → orient → plan ahead (v1.1).
  15. Prefer a native tooltip over new UI for supplementary detail — real usefulness, zero added visual weight (v1.1).
  16. State modules are context sentences, not "number + label" pairs — tint only where a semantic hue is genuinely earned, neutral when nothing needs saying (v1.3).
  17. Notifications tell the student what changed; actions tell them what to do — same row anatomy, but notification rows end in a quiet wayfinding mark, never a button (v1.4).
  18. Unread = bold text + soft 7% tint + dot (violet default, rose only for real urgency). Sidebar nav may carry a small semantic-hue count badge, gone at zero (v1.4).
  19. Language is plain and professional, never productivity-app jargon or emoji-decorated tags — "short task / extended work / dependent on another party," not "Quick Win / Deep Work / Waiting" (v1.6).
  20. Effort tags + filter chips match tasks to available time, filtering instantly with no reload; formal deliverables use review-stage language instead of effort tags (v1.6).
  21. Plain-line project snapshot (no card, no color block) is for lightweight orientation on a working page that already has its own hero — never a substitute for the Dashboard's full Project Command Center (v1.7).
  22. Deliverable rows are compact and collapsed by default; internal sub-items expand in place via a chevron, never a new page or modal (v1.7).
  23. Two elevated-paper cards may sit side by side (1.3:1) when a page has exactly two modules worth isolating — same card material as always, never a general multi-column card grid (v1.8).
  24. A card's header may carry a soft two-tone ambient wash (its only appearance outside a hero/threshold) to mark it as the "formal, reviewed" half of a paired workspace — never applied to more than one card per screen (v1.9).
  25. Conversational rows (Requests only) expand in place into a dot+text timeline instead of navigating away; only content marked student-visible renders — internal discussion is excluded at the data layer, not just hidden in the UI (v1.10).
  26. A right-side sheet (380px, dimmed workspace behind, mini ambient-hero header) is for focused in-context creation/editing, capped at 3 steps (type → fields → read-only review) — never for browsing or an open-ended wizard (v1.11).
  27. List cards keep a fixed element order — avatar → title (single-line ellipsis) → type tag → owner metadata → trailing attention signal, which never shrinks or truncates (v1.12).
  28. Ambient is the primary visual identity, not violet: the violet→neutral→aqua composition runs through every screen at page/section level; violet itself steps down to accent duty (actions, active states, Pulse) and never simultaneously carries navigation, links, statuses, badges and decoration (v2.0).
