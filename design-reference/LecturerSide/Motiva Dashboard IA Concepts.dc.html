DASHBOARD · INFORMATION ARCHITECTURE EXPLORATION

Four ways to answer "where's my project" in 5 seconds.

Same Design System throughout — same colors, type, radii, shadows, materials. Only the priority and arrangement of information changes. Layout sketches are intentionally low-fidelity; the goal here is structure, not finish.

AProject Command Center

Status leads, actions follow.

PROJECT OVERVIEW

REQUIRES ATTENTION

UPCOMING

HIERARCHY

  1. Progress, milestone, deadline
  2. Requires my attention
  3. Upcoming submissions

Rationale: answers "where am I" first, which stays true across every visit — a fact that doesn't go stale like a single task does.

+ Never feels like a to-do list; reinforces "companion," not "task manager."

– On a calm week, students scroll past status to reach the one thing they actually need to act on.

BAction First

What needs you, right away.

REQUIRES ATTENTION

UPCOMING

PROJECT STATUS

HIERARCHY

  1. Requires my attention
  2. Upcoming submissions
  3. Project status (compact, lower)

Rationale: optimizes purely for the 5-second test on a busy day — nothing sits between the student and what's blocking them.

+ Fastest path to action; nothing wasted above the fold.

– On a clear week (nothing pending) the page opens nearly empty — no reassurance that things are on track, which cuts against "confidence."

CProject Snapshot

Everything at a glance, one merged feed below.

SNAPSHOT STRIP

EVERYTHING · SORTED BY URGENCY

HIERARCHY

  1. One compact status strip (progress · milestone · deadline · counts)
  2. Single unified list — tasks + requests, sorted by urgency, no separate sections

Rationale: removes the "which section do I check first" decision entirely by merging tasks and requests into one ranked feed under a thin status bar.

+ Most compact, least scrolling; scales well as items grow.

– Loses "requests are a conversation, tasks are a checklist" distinction the rest of the product relies on; needs strong type-icons to stay legible.

DWorkspace

No hero at all — the calmest read.

TODAY

THIS WEEK

PROJECT PATH

HIERARCHY

  1. One quiet line of context (no card, no ambient hero)
  2. Today · this week · path — three plain list groups, equal visual weight

Rationale: tests the manifesto's calmest instinct literally — is a status hero even necessary, or does a well-ordered list already answer the question?

+ Truest to "calm companion, not a dashboard"; fastest to build and extend.

– Weakest at conveying momentum/progress — no single glance answer for "how much progress have I made," which the brief explicitly asks for.

Recommendation, if asked: A is what we already built and matches the brief's stated success criteria most directly. C is worth a closer look if the task/request volume grows — it's the most scalable structure. B and D are useful stress-tests of "how far can we lean into action-only or calm-only" but each drops one of the four required answers.
