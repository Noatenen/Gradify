REFERENCE IMPLEMENTATION · DASHBOARD

Dashboard: the system, in use.

Built entirely from the Visual Manifesto and Design System — no new tokens, materials or components invented for its own sake. Where the system was genuinely insufficient, the gap is called out below before the fix is applied.

01 · DESIGN RATIONALE

Why the dashboard is shaped this way

One ambient moment, then paper. The greeting is the only threshold on this page — it's a session start. It washes the top of the screen and dissolves into paper by the time the milestone module begins. No ambient behind the sidebar or the lists.

One card, not six. Per the system, cards are earned. The milestone tracker is the only true elevated-paper card — it's the one thing on this page worth isolating, because "where am I in the project" is the single question a student opens the dashboard to answer. Everything else — needs-you items, upcoming submissions — is rows on shared paper.

No KPI tile grid. The manifesto explicitly rules out admin-style metric tiles as the first thing a student sees. Instead, counts live as quiet inline numbers inside section labels ("Needs you today · 2") — present, not performing.

Status in words + the glow, not badges. "Overdue" is rose text + a dot. Nothing is a filled colored pill. This is the single biggest visual difference from the original exploration doc.

The one highlighted action ("today's focus") gets a contained ambient tint inside its card — the only place ambient reappears mid-page, and only because it's coaching a specific next step, which is exactly what ambient is for.

04 · DESIGN SYSTEM ADDITIONS

One small, named gap — everything else held

Gap found: the system defines "Rows" and type roles, but has no named pattern for the small heading that introduces a row group ("Needs you today · 2"). Without one, a designer might reach for a Heading-role title, which is too loud for what should be a quiet grouping label.

Minimal addition — "Section Label": Label/micro role (11px, 800 weight, tracked), muted ink, optional inline count in the same weight, 12px bottom margin before the row group. No new color, no new radius, no new material — just a formalized composition of existing tokens. Added to the Design System's Components section under Rows.

05 · DEVELOPER IMPLEMENTATION NOTES

Build notes

  • Layout: CSS grid, 1fr 248px (RTL: sidebar first in DOM, placed via border-inline-start so it mirrors correctly for LTR locales).
  • Ambient header is a fixed-height gradient block that scrolls with content — it is not fixed/sticky, so it only ever appears once per page load, per the "moments not locations" rule.
  • Milestone timeline: nodes are 26px circles on a 2px connector; state via 3 modifier classes (done/current/upcoming) — no per-instance inline color overrides in production code.
  • Status glow dot: 6–7px circle, color = semantic token only (rose/teal/violet); never combine with a filled badge background.
  • Section Label + row group is one reusable component (new, see §4) — count is live data, not hardcoded.
  • Buttons: exactly one primary (#4F46E5 solid) visible per viewport at a time — the "today's focus" CTA is the only primary on this screen; row actions use secondary/outline.
  • Motion: row hover = 1px shadow increase, 120ms ease-out. Card entrance on load = 320ms ease-out fade/slide-up, staggered 40ms per row. Ambient header fades in over 480ms ease-in-out.
  • Accessibility: 2px violet focus ring on all interactive elements; status conveyed by dot + text (not color alone); minimum 44px hit target on row action buttons on touch breakpoints.
  • Responsive: below 1100px, sidebar collapses to a bottom tab bar (paper, no glass); milestone card and row groups stack full-width.

06 · REFINEMENT PASS

From strong first pass to flagship

Sidebar. Active state moved from a dot-only marker to dot + a faint 5.5%-opacity violet wash behind the row — enough hierarchy to read at a glance, still far under "colorful." Nav rows gained a quiet hover wash (3.5% ink) and 2px more vertical gap for rhythm. A soft, tightly-contained violet glow now sits behind the wordmark's own dot — reusing the signature glow rather than adding a new device. Reinforces: signature glow, "color appears on 2–3 elements," material restraint.

Card fatigue. "Needs you today" and "Upcoming submissions" lost their bordered white boxes — they're now bare rows on paper, separated only by a hairline under the section label. "Today's focus" lost its shadow and border; it's now a flat tint wash, closer to a highlighted zone of paper than an object floating on it. The milestone tracker is the only remaining card, because it's the one thing this page is asked to isolate. Reinforces: "rows are the default, cards are earned."

Vertical rhythm. Section spacing went from 28px to 44px; the ambient header gained 16px of breathing room. Larger, consistent gaps do more work than any container ever did to separate ideas.

Section titles. Labels moved from muted gray (#8B8698) at 12px to a slightly darker, more legible ink-gray (#5B5568) at 13px, plus a hairline rule beneath — still quiet, but now anchor their row group instead of nearly disappearing into it.

Primary CTA. Same violet, but now a subtle top-lit gradient (two adjacent violet tones, not a second hue) and a tighter, softer shadow — reads as one confident, well-lit object rather than a flat saturated block. No new color introduced.

Emotional moment. The current milestone node now breathes — a 3.2s, near-invisible box-shadow pulse between 4px/14% and 9px/5% opacity. Everything else on the page (rows, header, focus card) gets one 400ms fade-up on load, staggered slightly — the page feels like it settles into place rather than snapping in.

No new colors, radii, materials or components were introduced. The single addition is a motion token (below) — everything else is the existing system applied with more restraint.

Proposed Design System addition

"Ambient breathe" motion token: a 3.2s ease-in-out infinite box-shadow pulse (4px→9px spread, 14%→5% opacity, brand hue only), reserved for exactly one element per screen — whatever represents "you are here right now" (a current timeline node, an in-progress indicator). Added to the Design System's Motion section alongside the existing timing/easing tokens. Not for hover, not for multiple elements at once — its rarity is what keeps it calm.

07 · UX REVIEW — FROM UI TO USEFUL

The 30-second test

If Noa opens Motiva for 30 seconds before going back to work, she should leave knowing exactly one thing to do next. The changes below are all in service of that, not visual polish.

1 — The hero now answers "what kind of day is today," not just "hello." The greeting alone told Noa nothing actionable — she had to read three more sections to find out what mattered. The hero copy is now generated from project state ("one overdue item stands between you and the next milestone") and carries the primary CTA directly. In 30 seconds, this line alone is enough.

2 — "Today's Focus" was deleted, not restyled. It duplicated exactly what the hero now says and what the first row in "Needs you today" already showed — three places repeating one fact is decision fatigue, not guidance. Removing it is the single biggest clarity win on the page.

3 — Reading order now follows the decision, not the data model. Old order: progress card → action items → upcoming → generic tip. New order: hero decision → what needs you today → where you are on the path → what's coming later. Progress-as-context now comes after the action, because "what do I do" outranks "how far along am I" when time is scarce.

4 — Timeline gained real detail without new chrome. Each node now carries a native tooltip (completion date on done steps, live % + due date on the current step, unlock condition on future steps). Zero added visual weight — the information is there for the 5% of visits that want it, invisible the other 95%.

5 — Information density held, not cut further. Reviewed against "does this help a decision": due dates, the overdue flag, and the milestone target all pass. Nothing else was added, and nothing else needed removing — the previous pass had already stripped the KPI-tile clutter.

Philosophy check

Calm

One decision surfaced, not five competing ones.

Focus

Hero CTA points at exactly one task.

Guidance

Copy explains why the task matters, not just that it exists.

Momentum

Milestone card reframes the overdue item as the last thing before progress.

Confidence

Removing duplicate guidance signals the product trusts Noa to act on one clear instruction.

New UX principles for the Design System

  • One decision per screen. If two modules would tell the student the same "do this next," merge them — the hero is the default home for that instruction.
  • Hero copy is state-driven, never a static greeting. It names the specific blocker or next step, generated from real project data.
  • Order by decision priority, not data hierarchy: act → orient → plan ahead. What needs you beats where-you-are beats what's-later.
  • Native tooltips over new UI for supplementary detail (dates, unlock conditions) — real usefulness, zero added visual weight.

08 · PROJECT-CENTRIC PIVOT

From greeting to Project Command Center

The hero no longer greets — it reports. It now shows the project name, overall progress, the milestone timeline (moved up from its own card), remaining milestones, a quiet three-number summary (open tasks, pending requests, days to nearest deadline), and a minimal three-column task-awareness strip (To Do / In Progress / Waiting). All of it is plain ink on the ambient wash — no colored tiles, no borders-as-cards — so "dashboard within a dashboard" stays calm rather than becoming an admin console.

This supersedes the previous hero rule ("state-driven greeting naming the blocker"). That rule solved decision fatigue for one-off visits; project-state-first solves it for every visit, because "where am I" doesn't go stale the way a single blocking task does.

One deliberate deviation: the requested flow mentions "Upcoming Meetings," but Motiva has no meetings feature in the current product — its equivalent is upcoming submissions/deadlines, which the app already tracks. Kept that section as "הגשות קרובות" rather than inventing a feature; flagging this rather than silently substituting.

"Today's Focus" stays removed. With the blocking task both named in "Requires my attention" and reflected in the deadline count above, a third restatement would reintroduce the exact redundancy the previous UX pass removed. Happy to reinstate if you want an explicit next-action line, but as specified it would duplicate.

Design System update

Hero rule, v1.2 (supersedes v1.1): the hero is a Project Command Center, not a greeting — project name, overall progress, milestone timeline, and a quiet numeric summary. Numbers stay as plain ink label+figure pairs separated by hairlines, never colored tiles. A mini task-awareness strip (counts only, no per-column color) may appear beneath it for products with a task pipeline — it shows awareness, never manages tasks; that stays on its own page.

09 · FROM REPORT TO CONTROL PANEL

Numbers with meaning, not numbers with labels

The hairline-separated stat row and the standalone Kanban strip were both table-like — correct data, report posture. They're replaced by three modular blocks, each phrased as a sentence a student would actually think: "2 things waiting for you today," "on pace · 4 in progress · next submission in 17 days," "3 requests with the team — nothing needed from you." The third one is the important case: naming that a number does not require action is itself reassurance.

Color is now doing real work instead of decoration: violet tint marks the module that needs the student; teal tint marks the healthy/on-track module; the "not on you" module stays neutral on purpose — no color means nothing to worry about. This is the "three hues, always meaningful" rule applied one level deeper than before.

The label-removal test: covering every small caption, a student still sees "2," "on pace," "3" against three distinctly tinted blocks — the color and the bold word (not the label) carry the state.

Design System update, v1.3: project-state modules are phrased as short context sentences, never bare "number + label" pairs. Each module's tint is one of the three semantic hues chosen for real meaning (needs-you / on-track / not-on-you), or no tint at all when nothing is being communicated beyond a fact. No new color, radius or component — this refines the v1.2 hero rule's "quiet numeric summary" into "contextual state modules."

10 · NOTIFICATIONS, WITHOUT COMPETING WITH ACTIONS

What changed vs. what you must do

Placement (Option B, below "Requires my attention"): the page is one reading column by design — a second desktop-only column (Option A) would recreate the three-panel admin layout the whole system rejects, and would only ever be visible on the widest screens. Slotting "Recent updates" directly after the action list keeps the decision order intact: act → what changed → what's ahead.

Distinguishing the two sections is done entirely by content and by whether a row carries a real button. "Requires my attention" rows end in a solid/outline button (a decision to make). Notification rows end only in a quiet "‹" wayfinding mark (something to look at, not to resolve) — same row anatomy, different affordance, so they read as siblings, not duplicates.

Unread vs. read: unread rows get a small violet dot, bold text, and a very soft tint background; read rows lose all three and sit at normal ink-muted weight. Color intensity is the only signal that scales with urgency — an unread row about an updated deadline uses the rose dot instead of violet, because that one is time-sensitive; everything else stays on the calmer violet/neutral scale.

Capped at 3–4 rows with a single "View all" link to the Notifications page — the Dashboard gives awareness, never becomes the inbox.

ROW STATES, FOR REFERENCE

Unread, informational — bold text, violet dot, soft tint
Unread, time-sensitive — rose dot, reserved for real urgency
Read — no dot, muted weight, still legible
Empty state — "אין עדכונים חדשים. הכול מתקדם כרגיל." one calm line, no illustration
Overflow (5+) — list caps at 4, "View all" link replaces a 5th row

Design System update

v1.4 — Notification row + sidebar unread badge: notification rows share the Row component's anatomy (dot + text + trailing mark) but end in a quiet "‹" wayfinding mark instead of a button, keeping them visually distinct from actionable rows without a new container. Unread = bold text + soft tint (7% hue) + colored dot (violet default, rose only for genuine time-sensitivity). Sidebar nav items may carry a small pill badge (16px, semantic-hue background, white numeral) for unread counts — violet by default, disappears at zero, never oversized or animated.
